We meet 2 days a week for 4 x 45 minutes. The contents are on BS — mind the preparation section. Each lecture is structured into 4 session types:

- Exercises (45')
- Work on assignment (45')

## Learning outcomes and competencies

The course equips students with the knowledge and skills necessary to develop, manage, and optimize the server-side logic of web applications. At completion, students will be able to design, implement, and maintain the backend of a web application, ensuring that it is secure, efficient, and scalable.

Backend = Servers + API + Databases:

- **Servers** — exercised with Docker
- **API** — exercised with ASP.NET Core
- **Databases** — exercised with SQL Server and Mongo

This is a hands-on course (designed as a lab class). You will acquire the skills of a starting back-end dev.

Formally you learn how to:

- Design and implement a WebAPI that includes persisting data in a database.
- Apply container technologies to deploy the developed applications to servers in production environments.
- Apply user authentication and authorization.
- Apply libraries to implement two-way communication over the Web socket protocol.
- Summarize methods for selection and modeling of a concrete database technology.
- Compare data structures in databases with data structures in an application.
- Apply standard network technologies to provide network access to a given database.
- Analyze techniques to ensure correct data in a database and for sharing the responsibility for correct data between databases and applications.
- Apply different types of databases related to application development with help from development tools and programming methods.
- Describe the most common database subject expressions.

## Books

- **Web API development:** the course follows a book as reference. Chapters in the preparation section are a must to understand exercises and assignments. Details on BS.
- **Databases:** the DMAD book is used for the theory and methodology of relational databases. Of the MongoDB book, only the first 3 chapters are touched.

## Evaluation

- 4 assignments with pass/no-pass grade: two individual and two in groups.
- You must obtain a pass grade in all of them.
- If you fail an assignment you get a chance to re-hand in, but each assignment must be completed and approved no later than 14 days past its due date.
- Re-exam: none — solve the new assignments in the next semester.

## Assignments

Each assignment consists of:

- A hand-in submitted on BS by the deadline (typically code and report artifacts).
- A check in pre-defined lectures: oral discussion of the solution with a teacher or TA.

Hand-in and check details (requirements, grading, ...) are released circa 4 weeks in advance on BS. Check the general rules on BS — special attention to the late hand-in section.

## Checks

The check is an informal conversation about the submitted hand-in:

- You are expected to have your solution running on your machine.
- You are expected to describe what you accomplished — a pitch.
- You are expected to be able to discuss your decisions.

Note: in group work you should be able to do all the above for **all** the code, even parts a colleague developed. There will be a checklist for what to expect.
